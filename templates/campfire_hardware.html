Enclosure, Weight & Optics Sandwich

CNC Hardwood + Cast Acrylic

The Problem of "Digital Pepper" (Hotspots)

Standard consumer LED fixtures look cheap because human eyes instantly resolve individual LED emitter dies (the "dotted string" effect). For a believable fire installation, the timber block must appear as a solid glowing volumetric chunk of radiant mineral/wood material.

To eliminate all hotspot imaging while keeping the outer silhouette crisp, each log employs a 3-stage optical diffusion sandwich:

  • 1. Core Aluminum Spine: 20mm square extruded 6063-T5 aluminum tube acts as the structural spine, grounding wire conduit, and thermal heat sink absorbing 15W per log.
  • 2. Internal Silicone Diffuser: A 2mm translucent high-temp silicone sleeve fits directly over the 4-sided LED arrays, softening the primary 120° beam angle.
  • 3. Cast Acrylic Outer Shell: 5mm thick cast Plexiglas 0D010 (82% transmission, high diffusion coefficient), sandblasted on both inside and outside surfaces to produce a soft matte frosted velvet finish.
  • 4. Tactile Brass Ballast: Real wood logs have mass. Plastic cylinders feel like toys. Solid brass cylindrical slugs are pressed into the end caps to give each 30cm log a heft of 650 grams.

03

Polarity-Agnostic Magnetic Coupling

Zero-Worry Stacking

The Foolproof Stacking Problem

If a user stacks logs backwards or upside-down, a conventional DC connector would reverse polarity (+12V and GND flipped), instantly vaporizing microcontrollers and LED drivers.

Our design solves this using Concentric Circular Pogo Pads + Dual Ideal Diode Bridges:

  1. Concentric Ring Geometry: Center pin (Ring 0) carries Data; Inner ring (Ring 1) carries Pole A; Outer ring (Ring 2) carries Pole B. Because the contacts are circular, rotating the log around its axis never breaks connection.
  2. Schottky / Ideal MOSFET Rectifier: Each log receives power through an onboard low-$R_{DS(on)}$ dual N-channel MOSFET bridge (e.g. Texas Instruments LM74610). Whichever ring is +12V and whichever is GND, current is automatically directed into the correct internal rail with only 0.04V drop!
  3. PolySwitch Resettable PTC Protection: A 3.0A self-resetting polymer PTC fuse disconnects any log instantly in the event of an accidental metallic short across the outer pads.
PORT PINOUT SPECIFICATION 4-PIN CONCENTRIC POGO
Ring 0 (Center Pin): 1-Wire Bidirectional Topology Discovery
Ring 1 (Inner Track): Bidirectional DC Rail 1 (Schottky Bridge Input)
Ring 2 (Outer Track): Bidirectional DC Rail 2 (Schottky Bridge Input)
Ring 3 (Outer Shell): N52 Neodymium Ground Ring (Holding Force ~1.8kgf)
Magnetic Interlock: High-flux countersunk rare-earth magnets ensure logs "snap" affirmatively into alignment with a crisp mechanical tactile feel, preventing partial contact arcing.
04

3D Spatial Topology Discovery

How the Hearth Knows Where Logs Are

In our 3D web simulator, the computer knows the coordinates of every block in software. In real life, if you pick up Log #3 and lean it diagonally between Log #1 and Log #2, how does the system know its 3D angle and height so the flame field flows seamlessly through it?

hub

Step A: 1-Wire Adjacency Tree

Every docking face of each log contains a Maxim DS2401 Silicon Serial Number chip. When two faces touch, the master hearth pings the 1-Wire network. By pulsing pull-up resistors on each port in sequence, the master builds an instantaneous graph adjacency matrix:

HEARTH_DOCK_1 ──> LOG_01 (Face A)
LOG_01 (Face C) ──> LOG_04 (Face B)
LOG_04 (Face D) ──> LOG_06 (Face A)

Now the firmware knows the exact hierarchical connectivity tree of who is stacked on top of whom.

screen_rotation

Step B: 6-Axis Gravitational IMU

Each log contains an ultra-low-power I2C 6-axis accelerometer & gyroscope (LSM6DSOX or MPU-6050). At rest, the accelerometer reads the Earth's gravity vector ($\vec{g} = [g_x, g_y, g_z]$).

Pitch = atan2(-gx, sqrt(gy² + gz²))
Roll = atan2(gy, gz)
Orientation = Absolute 3D Tilt Angle Vector

Combining the Adjacency Tree with the Tilt Vectors allows forward kinematics to calculate the absolute 3D position $(x, y, z)$ of all 512 individual LED pixels in space!

Volumetric Flame Math & Firmware

ESP32-S3 Dual-Core Pipeline

Traditional LED fire effects look repetitive because they scroll a pre-baked 2D flame bitmap. In our physical installation, every LED is a voxel (volume pixel) sampling an invisible, continuous 3D turbulent convective flow moving up through room space at 60 FPS:

1. Volumetric Simplex Field

For each LED at coordinate $(x, y, z)$, the thermal intensity $T$ is computed by sampling 3 octaves of Simplex noise:

T(x,y,z,t) = Simplex3D(x*fx, (y - v*t)*fy, z*fz)

The upward velocity parameter $v$ creates natural buoyancy where flame eddies rise and curl.

2. Conductive Heat Simulation

Each log maintains an internal "core temperature" variable. When logs touch, heat flows via conductive diffusion:

dH/dt = k * (T_neighbor - T_self) - C_dissipate

Placing a cold new log on top causes it to "catch fire" over 3 to 5 seconds as heat conducts into it!

3. Blackbody Color Gradient

Thermal energy $T$ maps into realistic non-linear Planckian blackbody radiation:

T < 0.35: Deep Carbon Ash (#1a0400)
T = 0.60: Crimson Ember (1800K)
T = 0.85: Radiant Amber (2400K)
T > 0.95: Plasma White Spark (3500K)

An exciter has no speaker cone: it drives acoustic vibrations directly into solid materials, turning the entire wooden hearth and whichever table or floor it sits on into a giant, warm, resonant acoustic soundboard!

Firmware Core Code (ESP32-S3 C++)

FastLED + Simplex Volumetric

Here is the production-ready C++ embedded algorithm running on Core 0 of the ESP32-S3. It samples 3D volumetric Simplex noise for every physical LED coordinate and translates it into blackbody thermal radiation:

CampfirePhysics.cpp Target: ESP32-S3 (Arduino-ESP32 / ESP-IDF) 
#include <FastLED.h>
#include <SimplexNoise.h> // Fast integer 3D simplex implementation

#define NUM_LOGS 8
#define LEDS_PER_LOG 64
#define TOTAL_LEDS (NUM_LOGS * LEDS_PER_LOG)

CRGB leds[TOTAL_LEDS];
SimplexNoise simplex;

// 3D Physical Spatial Coordinates of each LED voxel (updated by IMU/Topology engine)
struct VoxelPoint {
    float x, y, z;      // World space in centimeters
    float coreHeat;     // Conductive heat accumulator [0.0 - 1.0]
    uint8_t logId;
};
VoxelPoint ledVoxels[TOTAL_LEDS];

// Blackbody radiation color temperature lookup
CRGB kelvinToCRGB(float kelvin, float intensity) {
    // 1800K (Crimson Ember) -> 2400K (Warm Amber) -> 3200K (Golden White Flame)
    float t = constrain((kelvin - 1600.0f) / 1600.0f, 0.0f, 1.0f);
    uint8_t r = (uint8_t)(255 * intensity);
    uint8_t g = (uint8_t)(constrain(t * 180.0f, 0.0f, 180.0f) * intensity);
    uint8_t b = (uint8_t)(constrain(pow(t, 2.5f) * 70.0f, 0.0f, 70.0f) * intensity);
    return CRGB(r, g, b);
}

void renderVolumetricFlameFrame(float timestampSeconds) {
    const float convectionSpeed = 1.4f; // Vertical rise speed (cm/s)
    const float noiseScale = 0.08f;     // Spatial frequency
    
    for (int i = 0; i < TOTAL_LEDS; i++) {
        VoxelPoint& v = ledVoxels[i];
        
        // Compute upward traveling turbulence coordinate
        float sampleX = v.x * noiseScale;
        float sampleY = (v.y - (timestampSeconds * convectionSpeed)) * noiseScale;
        float sampleZ = v.z * noiseScale;
        
        // 2-Octave 3D Simplex Turbulence Field
        float noise = simplex.noise(sampleX, sampleY, sampleZ);
        noise += 0.5f * simplex.noise(sampleX * 2.1f, sampleY * 2.1f, sampleZ * 2.1f);
        noise = (noise + 1.5f) / 3.0f; // Normalized [0.0, 1.0]
        
        // Base height gradient: Bottom logs maintain dense ember bed; top licks flicker
        float heightAttenuation = constrain(1.0f - (v.y / 45.0f), 0.15f, 1.0f);
        float thermalEnergy = noise * heightAttenuation * v.coreHeat;
        
        // Map thermal energy to Kelvin blackbody color
        float kelvin = 1600.0f + (thermalEnergy * 1600.0f);
        float brightness = constrain(thermalEnergy * 1.3f, 0.05f, 1.0f);
        
        leds[i] = kelvinToCRGB(kelvin, brightness);
    }
    
    FastLED.show();
}
